x402-grocery

Real grocery product search and cart building over the Kroger API — every query paid per request with x402 micropayments. No accounts, no API keys for callers.

Pricing

RoutePriceWhat you get back
GET /products?q=$0.002Products with prices, promos, aisle locations, stock levels
POST /cart$0.005Fully priced cart: line items, substitutions, subtotal, tax, total
GET /healthfreeService status + active data source
GET /.well-known/x402freeMachine-readable discovery manifest

How a paid call works

1 · RequestAgent calls GET /products
→
2 · 402Server quotes price in USDC (payment requirements JSON)
→
3 · PayClient signs USDC authorization, retries with X-PAYMENT
→
4 · 200Artifact in the body + settlement receipt header

Quickstart for agents

import { privateKeyToAccount } from "viem/accounts";
import { wrapFetchWithPayment } from "x402-fetch";

const account = privateKeyToAccount(process.env.PRIVATE_KEY);
const payFetch = wrapFetchWithPayment(fetch, account);

const res = await payFetch("http://localhost:4021/cart", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ items: [
    { query: "whole milk", quantity: 1 },
    { query: "eggs", quantity: 2 },
  ]}),
});
const cart = await res.json(); // priced cart, substitutions, totals

Live Kroger data with free developer keys (KROGER_CLIENT_ID/SECRET); a deterministic fixture catalog labeled "source": "fixture" otherwise — the demo never needs a paid key.
